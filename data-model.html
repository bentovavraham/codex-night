ActiveAcq — Budget Data Model

How projects, phases, and financial data are structured — and exactly what feeds into each budget column

1 · Core hierarchy

Every dollar in the system traces back through this chain. A Phase is the atomic unit of budget tracking — it is completely isolated from every other phase in the database.

🏗 Project e.g. "Madison Marquette"
📁 Phase e.g. "Phase 1 — Entitlement" · each phase has its own silo of budget rows, contracts, and invoices
📊 Phase Budget Lines one row per task, each linked to a QB GL account · the rows of the budget grid
📋 Contracts one per vendor agreement · assigned to one or more budget lines
🔄 Change Orders formal scope/cost changes · with per-line GL + task assignment
💵 Invoices billing documents · Fixed / T&M / Expense · with per-line GL + task assignment
🏷 QB Accounts (Chart of Accounts) shared GL code hierarchy · parent accounts group budget lines across all phases

2 · Phase isolation — the golden rule

Each phase is its own project

No invoice, contract, or change order from one phase can appear in another phase's budget — ever. Every query that aggregates financial data is scoped by phase_id or by phase_budget_line_id (which is globally unique and inherently phase-specific). GL-code-driven paths carry an explicit inv.phase_id = pbl.phase_id guard so that matching by account number never bleeds across phases.

There are three ways a record is scoped to a phase:
① By pbl.id — phase_budget_line_id = pbl.id · pbl.id is a globally unique integer; it can only belong to one phase.
② By phase_id directly — invoices.phase_id = phases.id · set when the invoice is uploaded.
③ Via contract chain — contracts.phase_id = phases.id · change orders inherit this via their parent contract.

3 · Budget grid — where each column's number comes from

Column What it represents Source table(s) Scoping mechanism

CONTRACTED

EXPENSE
 Reimbursable expense charges billed here invoice_line_items (billing_type = 'expense') Same cascade as FIXED
BILLED

AMT DUE

The QB Source tab replaces FIXED/T&M/EXPENSE/BILLED/PAID with numbers from qb_transactions (imported from QuickBooks), scoped to the phase by qb_transactions.phase_id = $1. The Compare tab shows both side by side.

4 · Invoice allocation cascade — how an invoice line item finds its budget row

When an invoice is saved, each line item is matched to a budget row using the following priority order. The first path that matches wins. The cascade applies identically to Fixed, T&M, Expense, Billed, and Paid columns.

Invoice Line Item → Phase Budget Line matching (runs for every invoice_line_items row)
P1
Explicit task assignment
The line item has been directly assigned to a specific budget row by Richard or the PM via the Edit modal.
ili.phase_budget_line_id = pbl.id
Scoped by pbl.id
P2
GL code match (unique GL)
The line item has a QB GL account assigned but no explicit budget row. It lands on the one budget row in this phase that uses the same GL code — only when that GL code is unique in this phase.
ili.qb_account_id = pbl.qb_account_id AND inv.phase_id = pbl.phase_id AND no other pbl in this phase shares the same GL code
Scoped by phase_id + GL
P3
Legacy: invoice-level assignment (no line item GL)
Line items that predate the current model — they have neither a pbl assignment nor a GL code. The system falls back to the parent invoice's own phase_budget_line_id.
ili.phase_budget_line_id IS NULL AND ili.qb_account_id IS NULL AND inv.phase_budget_line_id = pbl.id
Scoped by pbl.id
Transitional — disappears as invoices are re-saved
P4
Legacy: invoices with no line items at all
Old invoices imported before the line-item model existed. The whole invoice amount lands on the budget row that the invoice itself points to.
inv.phase_budget_line_id = pbl.id AND no invoice_line_items rows exist for this invoice
Scoped by pbl.id
Transitional — disappears as invoices are re-saved

Shared-GL "General — Unassigned" rows: When the same GL code is used by 2+ budget rows in a phase (e.g. 1720.01 has both "Concept Plans" and "Site Plans"), Path 2 does not apply. Instead, unassigned line items for that GL code appear as a synthetic General — Unassigned row. As Richard edits each item and assigns it to a specific task (Path 1), the General row burns down toward zero.

5 · Change order allocation cascade

Change Order Line Item → Phase Budget Line matching
P1
Explicit task assignment
CO line item explicitly assigned to a specific budget row in the edit modal.
col.phase_budget_line_id = pbl.id
Scoped by pbl.id
P2
GL code match (unique GL)
CO line item has a GL code but no pbl assignment. Matches to the unique budget row for that GL code in this phase. Scoped via the parent contract's phase_id.
col.qb_account_id = pbl.qb_account_id AND contracts.phase_id = pbl.phase_id AND GL is unique in phase
Scoped via contract → phase_id
P3
Legacy: CO with no line items
Old change orders that were saved as a single amount with no line items. Fall back to the parent contract's budget row assignment.
c.phase_budget_line_id = pbl.id AND no change_order_line_items exist
Scoped by pbl.id

6 · Invoice types — what counts against what

Fixed Scope
Lump-sum billing
Vendor invoicing for work scoped in the original contract or a change order. You agreed to pay a set amount for a defined deliverable.
Counts against contract committed value. Triggers overspend warning if it exceeds the remaining balance.
T&M
Time & Materials billing
Vendor invoicing hours at an agreed rate — for open-ended tasks like engineering meetings, coordination, or inspection time.
Does NOT erode the fixed contract value. Shows as additional project cost beyond committed scope.
Expense
Reimbursable expenses
Vendor billing back pass-through costs: mileage, tolls, hotels, printing, etc.
Does NOT erode the fixed contract value. Shows as additional project cost alongside T&M.

Invoices have an extra Pushed status between Approved and Paid (exported to QuickBooks but not yet confirmed paid). Any step can be rejected with a required note. Rejecting resets the entire chain to Pending. Items are only counted in budget columns when status is approved, pushed, or paid.
